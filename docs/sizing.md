# サイズの規則づくり（M4）の準備：できていること・残り

設計書 12 章の準備部分。実際の比較の計算は、M3（決めた設定）と速さの目処が立ってから行う。

## できていること（crates/sizing）

- `features`：スートに依存しないボードの特徴。
  フロップ：一番高いカードの高さ（A / K / Q・J / T〜8 / 7 以下）、ペア（なし / あり / トリップス）、スート（レインボー / ツートーン / モノトーン）、
  つながり（同じストレートの範囲に入るランクの数：0〜1 / 2 / 3 以上。A は 5 ハイのストレートでも数える）。
  ターン・リバー：新しいカードの種類（ボードがペアになる、フラッシュ完成、ストレート完成、オーバーカード、フラッシュドローの出現（ターンのみ）、ブランク。この順で優先）。
- `flops`：1,755 のフロップ（22,100 通りを同型でまとめたもの。重み付き）と、代表 200・確認用 80 の選び方。
  特徴の組み合わせ（61 種類）ごとに最低 1 つ、残りは実際に配られる頻度に比例して選ぶ。シードで再現できる。確認用は代表と重ならない。
- `rules`：規則の表（JSON）。空欄は「何でもよい」で、一致する項目が一番多い行が勝つ。プレイヤー（IP / OOP）、チェックのあとのベットかどうか、ストリート、特徴で分けられる。`into_size_rule()` でゲーム木のサイズの規則になる。
- `compare`：方法 1。候補のサイズごとに 1 サイズの木を解き、ベットする側の均衡の EV が一番高いものを選ぶ。勝ち残り方式（全候補を 4% で解き、上位 2 つを 1.5% で比べる、が標準）。
- `sizing` コマンド：`sizing select`（代表と確認用のフロップ）、`sizing flops`（1,755 の一覧と特徴）。
- テスト：特徴の例、スートの付け替えで特徴が変わらないこと、1,755 と 22,100 の検算、選び方の再現性と重なりのなさ、規則の優先順位、JSON の往復、
  二極化レンジのリバーで一番大きいサイズが選ばれること。

## 残り

1. **スートの同型との両立**：今の `SizeRule::Custom` は同型の削減を無効にする（M1 の安全策）。規則の表はスートに依存しない特徴だけで決まるので、
   tree に「スートに依存しないカスタム規則」の印を足して、削減を有効にする（M2 の変更が入ったあとに行う）。
2. **ターン・リバーの比較**：フロップの均衡から、ターン（リバー）開始時の両者の到達レンジを取り出す API を solver に足し、
   そのレンジからターン（リバー）だけを解いて比べる。
3. **規則の作成**：代表の状況での比較結果から、表の行を作る（同じ特徴の組み合わせで多数決、EV の差が小さいものはまとめる）。
4. **確認**：確認用の状況で、規則のサイズと最適なサイズの EV の差（損失）を測る。目標は平均でポットの 0.1% 未満、最大 0.5% 未満。
