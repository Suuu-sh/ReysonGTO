## 目的と比較の境界

M2c の固定参照木ではなく、合意した本番ゲームを解くための設定と API を整備します。
レーキ、ドンク、ベットサイズ、merge、DCFR の γ、保存精度が M2c と異なるため、
**M2c や外部参照との収束時間・EV・戦略差を同条件の比較として扱いません**。
入力レンジの非対称なコンボ頻度はそのまま使い、同型削減のために対称化しません。

エクスプロイタビリティは、各プレイヤーの平均戦略からの BR 改善量の和を 2 で割り、
そのゲームの開始ポットに対する % で表します。レーキありでも両者の改善量を測る定義です。
本番目標は **0.3% 以下**。1 ボード 30 分は計測上限、15 分は希望目標であり、全フロップ共通の性能保証ではありません。

## production / benchmark の分離

CLI の通常 `solve` は `--preset production` が既定です。
`--preset benchmark` は M2c の固定条件を明示的に再現するためのプリセットです。

| 設定 | production | benchmark |
| --- | --- | --- |
| 初期ポット / 残りスタック | 5.5 / 97.5 BB | 5.5 / 97.5 BB |
| チップ精度 | 1,000 units/BB | 65,536 units/BB |
| フロップ / ターン / リバーのベット | 33 / 66 / 66% pot | 50 / 50 / 50% pot |
| フロップ最初の OOP lead | なし（チェック固定） | あり |
| レイズ | 直前の street-total wager の 2.5 倍まで | 同左 |
| レイズ回数 | スタックまで無制限 | 同左 |
| オールインへの merge | 今回の支払額が残りスタックの 67% 以上 | 無効、スタック上限のみ |
| レーキ | ポットの 5%、上限 3 BB | なし |
| 保存精度 | f32 | i16 |
| DCFR α / β / γ | 1.5 / 0 / 2 | 1.5 / 0 / 4 |

ターン・リバーの OOP は通常どおり lead できます。フォールドはベット・レイズに直面したときだけです。
金額は整数チップに四捨五入し、`Action::Raise(amount)` は street-total ではなく**今回の追加支払額**です。
レーキはフォールド・ショーダウンのどちらも勝者の受け取りから引き、引き分けはレーキ後のポットを分けます。

`--bet 50` は全ストリートを 50% にします。
`--bet-flop` / `--bet-turn` / `--bet-river` は指定したストリートだけを上書きします。
`--rake` の単位は割合（5% は `--rake 0.05`）で、`--rake-cap` / `--pot` / `--stack` は BB です。
既存の M2c runner は指定済みの独立設定を維持し、production への変更を引き継ぎません。

## サイズ規則と同型の安全性

`tree::SizeRule` は次を提供します。

- `Fixed(f64)`: 全ストリート同じ割合。
- `PerStreet { flop, turn, river }`: JSON 保存できるストリート別の割合。
- `Custom(Arc<dyn Fn(&SizeContext) -> f64 + Send + Sync>)`: 一般のコールバック。同型削減は無効。
- `SuitInvariant(Arc<...>)`: スート名の入れ替えに不変な純粋コールバックであるとの明示的な宣言。

`SizeContext` はボード、ストリート、プレイヤー、first-bet、after-check を含みます。
ベット候補を増やすのではなく、**各判断でコールバックが返した 1 サイズだけ**を木に入れます。
コールバックはシリアライズできません。再現可能な JSON 設定には `Fixed` / `PerStreet` を使います。
33 / 66 / 66% は初期設定であって、サイズ選択の EV 学習・最適性が検証された規則ではありません。

`check_suit_invariance(seed, samples)` は、決定的に生成した 3 / 4 / 5 枚のボード上で、
全 24 スート置換と player / first-bet / after-check の組を検査します。
Engine の作成時には固定 seed の 64 ボードで検査し、失敗した宣言は stderr に警告を出して、
**そのサイズ規則を維持したまま同型削減だけを無効**にします。

これは任意の関数の全ボード不変性の証明ではありません。
実際に alias を作る際にも、置換後の各部分木の action / 金額 / 状態の一致を検査します。
サンプルが見逃した非同型を実木で発見した場合は、途中まで書いた alias と permutation をすべて戻し、
警告付きで削減なしにフォールバックします。`isomorphism_used` と merged-child 数も削減なしになります。
レンジの置換可否はコンボ集合と**頻度の厳密一致**に基づき、近い頻度を等しいとは扱いません。

## 到達レンジの取り出しとターン / リバーの解き直し

API は `Solution::reach_snapshot(node)`、`ReachSnapshot::with_card(card)`、
`solve_subgame` / `solve_subgame_with_progress` / `solve_turn` / `solve_river` です。
CLI は `solve --reach-node ID --reach-out snapshot.json [--reach-card 3c]` と、
`solve-subgame --state snapshot.json [--card 3c]` を提供します。
外部レンジから直接解く場合は `solve-subgame --board ... --pot ... --stack ... --oop-range ... --ip-range ...` とします。
フルレンジの本番フロップ例は `solve --preset production --board Qh8d2c --oop-range data/ranges/bb_call.json --ip-range data/ranges/btn_open.json --memory-mb 16384 --out solution.json` です。

スナップショットは、ボード、現在ポット、両者の残りスタック、過去の投資額、開始ポット、
単位、木設定、各自の到達レンジを保存します。
**解き直しに入れるのは OWN reach**:

```text
reach_p(combo) = 初期の own combo weight
                × そこまでの player p 自身の平均 action 確率の積
```

相手レンジとの compatible-joint marginal は入力にしません。
相手カードとの重なりは Engine で除外し、public card と重なるコンボは `with_card` で重み 0 にします。
共通の chance 係数は省略し、カード blocker は明示的に扱います。
表示・集計用の `ComboStrategy::reach_weight` は compatible-joint reach なので、
これを OWN range にそのままコピーすると blocker を二重に反映してしまいます。

スナップショット抽出自体は途中ノードを扱いますが、**解き直しはストリート開始のターン / リバーだけ**です。
3 / 4 枚の pre-chance スナップショットには `with_card` で次のカードを指定できます。
未決着のベット、判断途中、unequal stack は未対応として拒否し、推測で補いません。
解き直しは過去のポット全体を引き継ぎ、終端でレーキを 1 回だけ徴収します。

### EV の基準を揃える

EV は開始ポットの半分を基準にした値です。
新しいサブゲームの EV を元のフロップ開始フレームに戻す API は `snapshot.source_frame_ev` です。

```text
EV_source[p] = EV_subgame[p]
             + (snapshot.pot - snapshot.source_starting_pot) / 2
             - snapshot.invested[p]
```

過去の投資だけを引く式は、開始ポット中心の変更を見落とすため使いません。
未収束のフロップ戦略を条件付けしたサブゲームと、新規に解いたサブゲームの EV は一致を保証しません。
局所の exploitability と EV frame を揃えた上で、合成テストの差を記録します。

runner / 上のフルレンジ例の `--memory-mb 16384` は資源予算の明示的な拡大であり、
ゲーム木のルール、f32 精度、入力レンジを速度目的で変更するものではありません。

0.1 秒ごとの polling により process wall は hard 上限をわずかに越え得ます。

子は常に 1 つずつ実行し、exact PID の `os.wait4` で RSS / CPU を取得します。
hard timeout は直接の solver 子を kill して回収してから次へ進みます。
telemetry や過去の solver 子の資源を RSS に混ぜず、直接の子以外の子孫の停止は保証しません。
失敗・timeout では最終 exploitability / 反復数を null にし、最後の checkpoint を**途中値**として残します。
checkpoint で目標を達成していても、最終結果が欠ければ完了とは判定しません。
プロセス成功でも 0.3% 未達なら `all_targets_met=false` とし、未達を隠しません。

### BTN 最初の判断の集計

`after_check_strategy` の player=1、Check / 1 Bet の判断を取り出します。
`btn-first-strategy.json` の `classes` はソルバーが出した**compatible-joint 重み**のクラス表です。

### 通常 profile の主な仕事
