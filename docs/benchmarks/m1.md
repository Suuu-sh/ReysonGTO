### テストの内訳と対象

- cards: 3 normal + 1 ignored（ID 往復・役カテゴリ・100 万件・全探索）
- ranges: 3（JSON / クラス総量 / blockers / 不正入力 / canonical combo）
- tree: 6（具体額のレイズ連鎖・67% 境界・ドンク・fold 条件・all-in・rake・custom size・ノード上限）
- cfr unit: 8（両アルゴリズムのトイゲーム、ランダム O(n²) 対照、純粋戦略 BR 全探索、
  chance 質量、実際の同型削減、非対称入力、bit 決定性、memory/rake）
- cfr integration: 3（独立した私有カード＋物理 runout 全列挙、memory 拒否、allocation）
- solver: 2（任意ノード戦略・JSON・停止・メモリ上限）
- cli: 1（ボード文字列・BB 丸め）

トイゲームはベット 500 / ポット 1000、レイズなしの明示的な木です。
ベッターのベット中のブラフ割合 = 500 / (1000 + 2×500) = 25%、
コール頻度 = 1000 / (1000 + 500) = 66.6667% を各 1 percentage point 未満の誤差で検査します。
BR は純粋戦略の全列挙と照合しています。
同型テストはフラグの切り替えだけでなく、実際の枝削減数 > 0 と全判断戦略・BR の一致を確認します。
チャンス確率は公開カードだけでなく両プレイヤーの 4 枚を除いた `1 / (52 - board_len - 4)` です。

## ベンチマーク

意味のない合成 3 コンボ対 3 コンボのみ。開始ポット 2 BB、スタック 1 BB、
ベット 50%、レイズ 2.5 倍、all-in まとめ 67%、レーキ 5% / cap 3 BB、OOP 先行可。
20 反復、目標 0%、上限 300 秒、同型有効。
この浅い木では初回ベットが all-in になります。深いスタックやフルレンジの性能指標ではありません。

- 訓練 1 反復 = OOP + IP の更新。毎反復の metrics（平均 EV と BR の 4 走査）は除外。
- solve 全体は初期 metrics と毎反復 metrics を含み、木構築・事前評価は含めません。
- 終端割合は同じ設定を **別途 1 スレッドで計測**した、終端 kernel 時間 / solve 壁時計時間です。
  並列ワーカー時間の合計 / 壁時計時間は 100% を超えうるため、この割合には使いません。
- メモリは状態・アリーナ・ランク表・履歴・25% の余裕・1 MiB/worker を含む推定で、RSS 実測ではありません。
- 代表枝にまとめた数（各 chance node の合計）: river 0、turn 78、flop 2,223。
- タイマー計測・スケジューリングの影響が大きい小規模ベンチです。1 回の測定であり性能保証ではありません。

## 設計書との差・制限・判断

1. **精度の分母**はユーザー指定を優先し、フロップ限定ではなく、その木の開始ポットです。
2. **同型削減は保守的な部分群**。両レンジの各コンボを個別に固定する置換だけを用い、
   複数コンボを入れ替える一般の同型を利用する最適化は未実装です。
   任意の非対称レンジを誤って統合しないための判断で、削減しない計算へのフォールバックは正確です。
   カスタムサイズはスート同変性を証明できないので削減しません。アリーナと保存領域は全枝を保持します。
   異なるランクのレインボーフロップは非自明なボード保存置換がなく、設計書の削減例は一般には成立しません。
3. **作業領域はノード単位の事前確保**で、スレッドごとの最小 stack scratch に詰める最適化は未実装です。
   後悔値・平均戦略・現在戦略は各 1 本の f32 配列で、並列枝へ排他的な連続 slice を渡します。
   ノード保存オフセットは木自身ではなく `Engine::strategy_storage_offset` にあります。
4. **ゼロ allocation** は公開 `solve` と `Engine::with_pool` 内の反復で検証しました。
   外部スレッドから低水準 `iterate` を毎回プールに投入すると Rayon の injector queue が
   断続的に確保されるため、低水準 API でもループ全体を `with_pool` に入れる必要があります。
5. **メモリは保守的な推定**です。アリーナは構築中のノード上限でも保護します。
   上限はプロセス RSS の強制制限ではなく、確保不能な全ケースを保証して防ぐ仕組みではありません。
6. **時間上限は反復境界の soft limit**。初期化は別計測で、反復や BR の途中では中断しません。
7. **EV の基準**は受取額 − 開始後の投資 − 開始ポット/2。
   fold 時のレーキ対象は設計書の式通り、その終端のポット全額（未コール分の別返却は扱いません）。
8. **M1 外**: i16 量子化、zstd/R2 保存、batch、サイズ探索、プリフロップ、配信 API。
   外部 OSS の出力比較も入力資料がないため未実施。OSS のソースや製品レンジは読み込んでいません。
9. 固定サイズ設定は完全に JSON 化できます。実行時 `SizeRule::Custom` クロージャ自体は JSON 保存できません。
