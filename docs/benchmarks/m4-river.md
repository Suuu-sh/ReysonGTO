# M4 リバー比較 runner

2026-10-18。実装と極小合成木の確認を扱う。**製品レンジでの比較、最適サイズの証明、独立 holdout 検証ではない。**
既存の M3/M4 計測と製品レンジは変更しない。

## 比較の条件

供給済み `configs/sizing/srp-btn-vs-bb.json` のフロップ・ターン規則を用いて
フロップを解き、XX / BC の到達レンジからターンを解く。
BC は OOP チェック → IP ベット → OOP コール。ターンでも XX / BC を取り出すため、
履歴は `XX→XX`、`XX→BC`、`BC→XX`、`BC→BC` の4通り。
今回のcheckoutには設定が存在し、`origin/main` と同一であることを確認済み。
別ブランチからの規則取得は不要だった。供給規則がない場合は停止し、固定値で捏造しない。到達元のリバーだけは66%固定。

`sizing river-cards --board 7c6d5d2h` は公開4枚だけを除いた48枚を分類する。
既知の両者hole cardsを除く44枚という条件はこのAPIには渡していない。
`--per-kind 1 --seed 20261015` で種類ごとの代表を選ぶ。スート同型はボードだけの同型で、
任意の非対称レンジの同値性を保証しない。空の種類を別カードで補完しない。

各リバー種類から代表カードを選び、OOP先打ち・OOPチェック後のIPベットを分離する。
対象判断だけ33 / 66 / 100 / 125%に変え、相手側は66%固定。
**全4候補を精度0.1%まで解く**（上位候補だけ再計算する方式ではない）。
勝者はベットする側のroot EV最大。損失は
`100 × (最大EV BB − 候補EV BB) / リバー開始時pot BB`。
これは収束指標とは異なり、raked general-sumの均衡EV誤差保証でもない。
1候補でも未達なら比較全体を未完了とする。

## 件数と時間の見積もり

既定は20フロップ、1フロップ最大3ターンカード。
20 × 3 × 4履歴 × 最大5リバー種類 × 2bettor = **最大2,400状況**。
4候補ずつで9,600リバーsolve、加えて120ターンsolveと20フロップsolve、計9,740solve。
空の種類や到達不能な履歴は実件数に影響し、この上限を必ず生成するわけではない。
ターンカード数は種類の数と混同しない。

代表計測の各段階のwall平均を F / T / R 秒とすると、
`20F + 120T + 9600R` が逐次実行の機械的外挿。
カード選択・I/O・再試行・収束差も別途考慮する。極小合成木の時間を本番見積もりには使わない。
種類別・bettor別の勝者集計は観測結果であり、全カード網羅や規則の汎化を意味しない。

## 極小合成木での実測・動作確認

`tools/test_m4_river.py` の実CLI integrationを1 threadで実行した。
入力は OOP `AcAd,KcKd` / IP `QcQd,JcJd` 各重み1、フロップ`7c6d5d`、
pot 2BB / stack 3BB、供給フロップ33%・ターン50%、`--max-turns 1`、
`--max-iters 3000 --target 0.1 --max-hours 0.1`。
合成レンジ・規則はテストの一時ディレクトリだけに生成し、製品レンジを読まない。

40/40状況が完了し、全160リバー候補が0.1%以下。4履歴・両bettorを実際に通った。
到達元はフロップ1solve、ターン2solve。カード選択2回を含む165attempt。
同じ入力の再開でattempt数は増えず、seedを変えるとprovenance不一致で停止した。
別の単体テストで成果物破損の再試行、bettor切替、pot比損失計算、目標未達時の未完了、
供給規則の優先順位・同点時の元の行順・直前ストリート履歴を確認した。

|段階|solve数|平均wall秒|
|---|---:|---:|
|flop|1|1.265670|
|turn|2|0.115267|
|river|160|0.115287|

最終受入確認の初回runner全体は21.919413秒。再開や拒否チェックを含む全14テストは23.720秒。
wallには子プロセス起動・watchdog待ちを含み、同時実行負荷のあるローカル環境の値。
**極小木の動作確認であり、この秒数から実レンジの完了時刻を約束しない。**

合成実測の平均を上限件数に機械的に当てはめると、
`20 × 1.265670 + 120 × 0.115267 + 9600 × 0.115287 = 1145.90064秒`
（約19.1分）。**これは合成木の数値外挿であり、本番所要時間の見積もりではない。**
実レンジ・実スタックでの分岐、収束、メモリ使用量の差を反映しない。

検証コマンド:

```sh
python3 -m unittest tools/test_m4_river.py tools/test_m4_turn.py
```
