## P1：木のルールと設計からの補足

- preflop 行動順は `UTG,HJ,CO,BTN,SB,BB` の存在する席順。postflop の相対位置は
  `SB < BB < UTG < HJ < CO < BTN` で、後ろを IP とする。
- 初期拠出は SB 0.5、BB 1BB と各席 ante。**stack_bb は ante を含む総持ち点**。
  レイズの `raise_to` 表示は ante を除いた live bet の到達額。
  内部遷移は **1BB=1,000 chips（0.001BB）** の整数。非有限値、負値、これより細かい額を拒否する。
- `--heads-up` は他席が既にフォールドした BTN/BB 局面を作る。
  SB の0.5BBと除外席の ante は dead money に残す。BTN 自体に SB を課す通常の2人卓ではない。
- 最初の行動は fold / 固定 open。非SBの open limp は入れない。SB のみ1BBへの complete が可能。
  BB には complete 後の check / iso が残り、SBには limp-reraise がある。
- 外部設定の固定到達額：open 2.5（SB3.5）、3bet IP8/OOP12、対SB open10.5、
  iso3.5、limp-reraise10.5、4bet IP26/OOP20、SB open→BB3betに対するSB4bet24BB。
- squeeze の base は IP12/OOP13BB。**最初のcallerを含む人数を n とし、base+(n−1)×2.5BB**。
  `per_additional_caller` は「最初に対する追加caller」と解釈した。
- 各段階で既参加者は call 可能。cold call は3betまでは可能だが、**4bet以降に新規に参加するcallは禁止**。
  forced blind / ante だけの支払いは、参加済みとして扱わない。raise 自体は禁止しない。
- 固定スケジュールのみで、各段階に任意の追加 jam を設けない。**5bet は jam**。
  それ以前でも固定額が総持ち点に達すれば jam。5bet後の相手は call / fold で、6betはない。
- **合法性のための設計補足**：`target=max(固定額, 現在額+直前のraise増分)`、最後に持ち点で上限化。
  例：2.5 open→12 squeezeでは直前増分9.5なので、名目OOP4bet20は違法。
  実際は **21.5BB** とする。callerが増えた大きなsqueezeでも同様に補正する。
  持ち点による短いall-inは許可する。全員同一総スタックのため、この木でside potは生じない。
- 終端は単独残存の fold、全員の行動が閉じた flop、all-in決着の3種類。
  foldはレーキ0。flop/all-inは `min(pot×rate,cap_bb)`。未コールraiseを含むfold終端も
  勝者 `pot−自分の拠出`、敗者 `−自分の拠出` として返却分を自然に含める。
- ノード上限は既定2,000,000。超過は明示エラーで打切り、不完全な木を成功扱いしない。

## P2：エクイティ表と誤差

169クラスは13×13行列、rank順 `A,K,Q,J,T,9,...,2`、対角pair、上三角suited、下三角offsuit。
physical combo は1,326（pair6、suited4、offsuit12）。
各クラス対で重複しないprivate-card組を一様に選び、残り48枚からboard5枚を一様sampleし、
M1の役判定で勝利1・引分0.5として集計する。PRNGは自前のseed付きSplitMix64。
各対に独立の決定的seedを使い、thread数・スケジューリングに結果を依存させない。

- 異クラスunordered pair：`169×168/2 = 14,196`。
- 各100,000 samplesで **1,419,600,000 boards**。逆方向は `1−equity` を保存。
- 同クラス対角は交換対称性から厳密に0.5で、sample不要。
- 1セルの標準誤差上限：`0.5/sqrt(100000) = 0.00158114`、**0.1581 percentage point**。
- 正規近似の95% pointwise半幅上限：`1.96×SE ≈ 0.003099`、**約±0.31 percentage point**。
  これは全14,196対に同時成立する保証でも、厳密な確率誤差上界でもない。
- JSONにはmethod、schema、seed、samples、上記誤差metadata、class順、全行列を保存。
  ロード時に順序・大きさ・有限性・[0,1]・対称性・対角・誤差metadataを検証する。

**設計からの差分**：all-inのboard完全列挙は行わず、ここでもMC表を使う。
また、表は合法なsuit配置で平均したクラス間equityであり、特定のphysical combo対の
suit条件付きequityではない。sampling誤差だけでなく、この抽象化誤差が残る。

終端では到達レンジのcard overlapを除く。自分の2枚を除いた相手combo数は
`C(50,2)=1,225`、合法ordered deal数は `1,326×1,225=1,624,350`。
blocker補正はこれらの合法combo数で正規化し、重複カードの確率をゼロにする。
この**合法性補正が正確であることと、equity自体がcombo別に正確であることは別**。

2〜6人の `estimate_multiway(classes,samples,seed)` はライブラリのon-demand MC推定器として用意。
全員分のprivate-cardをまとめてsampleし、重複時は組全体を棄却して合法joint dealを得る。
同順位にはpotを等分し、各席equityの和は1。これは6人CFRや全組合せの永続表ではない。

## P3：DCFR・価値・実現率

各decision/actionに1,326コンボのregret・平均戦略を保持し、各席のreachも同じ次元で伝播する。
交互更新DCFR。第t回（1起算）の追加前に、既存の正regretへ `(t−1)^1.5/((t−1)^1.5+1)`、
負regretへ0.5、平均戦略累積値へ `((t−1)/t)^2` を掛ける。
これにより平均戦略の反復重みは1,4,9,...となる（regression testで確認）。
平均戦略には自分のrealization reachを使う。
終端がsuit不変ならそのことを検査してclass-kernelで高速化し、不変でなければ
per-card blocker subtractionに戻す。元のcombo次元を無条件に169へ削減するわけではない。

- fold：勝者 `pot−contribution`、他 `−contribution`。
- all-in：`equity×(pot−rake)−contribution`。
- flop：`equity×(pot−rake)×realization−contribution`。

実現率は**未学習のv1仮定**であり、ポストフロップsolverで検証した値ではない。
JSONの全値は以下。limp/SRP/3bet/4betは終端stageに対応し、all-inには実現率を掛けない。

ハンド分類はpair優先、次に同スートかつrank差1をsuited_connector（AKsを含み、A2sは含まない）、
残り同スートをsuited。offsuitで両rankがT以上ならoffsuit_broadway、残りoffsuit。
1を超える値は確率ではなく、equity比の実現係数。設定値は有限な[0,1.5]を要求する。

### 収束指標の意味

rakeと実現率により定和・ゼロサムではない。各席の平均戦略profileに対する
best-response EVとprofile EVを計算し、

`NashConv_BB = Σ_player (BR_EV − profile_EV)`

を報告する。`half_gap_bb=NashConv/2`も出すが、これをゼロサムのexploitability保証と呼ばない。
単位はBB、**各人の単独改善幅の合計**であり、pot比%ではない。
小さな値はこの抽象ゲーム内の平均戦略の安定性のみを示す。MC誤差、クラス平均誤差、
未学習の実現率、欠けたアクションによる真のゲームとの差を制限せず、真のGTO精度やEV誤差の保証ではない。
一般和でDCFRがナッシュへ必ず収束する、あるいは各checkpointで単調減少するとは主張しない。

## CLIと実行例

リポジトリrootから実行。表生成は重い独立ジョブなので、solveと同時実行せず、事前に計算量を確認する。

```sh
cargo build --release
CFG=/Users/yota/Projects/Products/ReysonAI/configs/cash-6max-100bb.json

# 6max全体と、他席fold後のBTN対BB
./target/release/preflop tree-stats --config "$CFG"
./target/release/preflop tree-stats --config "$CFG" --heads-up
./target/release/preflop tree-stats --config fixtures/preflop-hu.json

# このベンチ条件（CLI既定値は10,000なので100,000を明示）
./target/release/preflop equity-build \
  --samples-per-pair 100000 --seed 20261015 --threads 8 \
  --out data/equity/hu169.json
./target/release/preflop equity-check --table data/equity/hu169.json

# solveは常にBTN/BBへ射影する。実現率は明示必須
./target/release/preflop solve \
  --config "$CFG" --equity data/equity/hu169.json \
  --realization configs/preflop-realization.json \
  --max-iters 2000 --max-seconds 300 --metrics-every 25 --target-bb 0.00001 \
  --out out/m5/hu100-tight.json

# 別ゲーム：合成40BBの固定サイズHU
./target/release/preflop solve \
  --config fixtures/preflop-hu.json --equity data/equity/hu169.json \
  --realization configs/preflop-realization.json \
  --max-iters 2000 --metrics-every 25 --target-bb 0.00001 \
  --out out/m5/synthetic.json

# 別ゲーム：合成40BBで一度のshove/callだけ
./target/release/preflop solve \
  --config fixtures/preflop-hu.json --push-fold \
  --equity data/equity/hu169.json \
  --realization configs/preflop-realization.json \
  --max-iters 2000 --metrics-every 25 --target-bb 0.00001 \
  --out out/m5/push-fold.json
```

solve既定：最大2,000反復、300秒、50反復ごとに指標、target NashConv 0.001BB。
到達判定はcheckpointで行う。時間上限はstep直後に評価するsoft limitで、
初期化・当該step・指標計算・JSON保存によりwallは超過し得る。
停止理由 `target_bb` / `max_iters` / `max_seconds` を区別し、上限停止を収束達成と扱わない。
